# 铸造流程（PIPELINE）

> 本文档面向想深入了解本专家团内部机制的用户/贡献者。介绍团队铸造一支专家团的 9 阶段流水线、各阶段交付物与依赖的技能。

## 9 阶段流水线

工作流水线（SOP，即标准操作流程）共 9 步，严格按顺序走，一步不过关不进下一步：

```
Phase 1  铸造总监        听你说清需求，整理成一张《需求定义卡》
Phase 2  需求架构师      决定团队要有哪几个角色、各管什么、为什么需要
Phase 3  技能选型师      给每个角色挑最合适的技能，并确认本机真的能用
Phase 4  专家包工程师    把团队生成真正的包体，注册到你的 WorkBuddy
Phase 5  质检合规官      交付前全面体检 + 九维能力基线预检，问题严重可一票否决
Phase 6  铸造总监        正式交付，并附上「还差什么」的能力缺口清单
Phase 7  版本迭代官      给团队打分：首版建基线，升级版出裁决
Phase 8  铸造总监        实战验收，记录真实使用中的效果与效率
Phase 9  铸造总监        处理成员的自我改进提案，并把跨团教训回灌进模板
```

## 各阶段新增要点（v1.7.0）

下面几条是 v1.7.0 从实战教训里补进流水线的硬性要求，每一阶段都可能因此退回重做：

| 阶段 | 新增要求 | 来自哪个坑 |
|---|---|---|
| Phase 1 · 接需求 | **数据源可及性预判**：逐源标注登录墙 / 反爬 / 地域限制 / 软文污染 / 需凭据，不可及的须给替代路径与缺料标注方式；**个人信息与隐私口径**：是否涉及个人信息、最小必要与脱敏要求、遵守《个人信息保护法》（PIPL），产出物不得含手机号、身份证号、私人社交账号 | 采集项目连撞登录墙，报告结论无法支撑；PII=0 全靠成员临场自觉 |
| Phase 2 · 定编制 | **长时任务策略**：涉及采集 / 抓取 / 批处理时，须写清分片粒度 + 断点续作 + 中断后不重复消耗；**空技能声明**：`skills` 为空的角色必须声明「判断型无工具角色 + 理由」，否则编制不合格 | 会话中断杀死后台子代理，两次零产出；首版技能全空仍通过门禁出厂 |
| Phase 5 · 质检门禁 | **九维基线预检**：交付前跑一次九维评分，附实际输出与退出码，产出《能力基线卡》与缺口清单；**总分低于 70% 或缺口 ≥3 条默认不得交付**，须由你（用户）在「打回重做 / 知情放行」之间裁决，放行的交付说明必须标注「图纸级交付 + 缺口清单」 | 首版带 7 条能力缺口出厂，到迭代评估时才发现缺口规模 |
| Phase 8 · 实战验收 | **置信度校准误差算法**成文：采信等级（财报 / 官方公示 0.9、权威媒体 0.6、当事方自述 0.4、待定 0.2），误差 =｜等级均值 − 抽检通过率｜，抽检 ≥20 条，确实不可算的标 N/A；**中断与恢复事件**记录会话中断 / 子代理被杀的次数、影响范围、恢复方式，并写明分片策略是否生效 | L1 置信度校准只有指标没有算法，实测时算不出来 |
| Phase 9 · 提案处理 | **跨团教训回灌（V-6）**：Phase 8 的每条遗留议题都要归类为「本团议题」或「铸造局模板议题」，模板议题登记进 [LESSONS.md](LESSONS.md)，未落入模板字段的不得关闭，下一版铸造逐条核对 | 同一个坑，下一个团再踩一次 |

## 交付物清单

铸造完成时，你会得到：

- 一个装好就能用的专家包（放在 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/<团名>` 下）
- 四份证据文档：
  - 角色编制表（谁进团队、各管什么、边界在哪）
  - 技能选型表（每个角色用什么技能、为什么、实测结果如何）
  - 质检报告（交付前的全面体检结论 + 九维预检输出）
  - 能力基线卡或迭代裁决报告（首版建基线；升级版给出打分裁决）
- 一份「下次还能更好」的能力缺口清单

验收过的团队还会多两份记录：

- 运行基线卡（Phase 8 实跑后归档，记录交付质量与过程效率指标）
- 跨团教训回灌台账中与本团相关的条目（Phase 9 登记，见 [LESSONS.md](LESSONS.md)）

> 未经过真实使用验证的团队会标记为「图纸级交付」，以区分于实跑验收过的团队。

## 两个容易混淆的点

- **九维基线预检（Phase 5）与交付前基线卡（Phase 7A）是同一张卡**：Phase 5 预检产出的 JSON 就是 7A 的输入，不另起一张卡重跑；两处分数不一致即视为证据不实，退回重测。
- **评分与裁决规则、维度定义、分母口径**见 [SCORING.md](SCORING.md)；本文只讲流程与交付物。

## 依赖的技能

| 技能 | 被谁用 | 来源 |
|---|---|---|
| `expert-skill-selector` | 技能选型师、质检合规官 | 用户级技能 |
| `expert-manager` | 专家包工程师、质检合规官 | WorkBuddy 内置 |
| `team-capability-eval` | 版本迭代官 | 用户级技能 |

> 本团队**不自带**技能库，因此 `plugin.json` 中不声明 `skills` 字段。
